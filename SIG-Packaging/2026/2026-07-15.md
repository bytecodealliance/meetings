## New Package Manager - Yosh

* Yosh: I have a new package manager
  * Victor: it's more than a package IIRC
  * Yosh: It has been vibed a bit
* Yosh: It's called wasm directory, you can browse it
  * https://wasm.directory
  * https://wasm.directory/wasi/http/0.3.0
  * It's a "meta-registry", which
    * Does cross-package dependency resolution (not just name based)
    * Uses flat files for metadata
    * Goes through once an hour and tries to get updates
* Victor: What's the over all flow? Do I search the registry
  * Yosh: Yes, you go there and can search for interfaces you need
* Victor: Do you need something from wkg?
  * Yosh: We make a differentiation between components and WIT interfaces
  * Yosh: Right now, a lot of it is competing -- `component` CLI has a bunch stuff (e.g. has `component run`)
    * Ideally, it would be great if we could upstream this to the BA
    * Would really like for this to be a frontend to wasmtime
* Calvin: The BA can't really run a service
  * Yosh: In general the BA definitely doesn't want to be on the hook for hosting packages
    * The sites are static though, so easy to generate
  * Calvin: What about ingesting?
    * Yosh: Yeah there's some storage though, relatively little though
* Victor: Could we figure out what the full feature set and how we could get it in
  * Yosh: It may be easier to just try it out? There's a bit of a running service that works together
* Mikhail: I've taken a super cursory look, and don't see a ton of overlap with the features that went into `wkg`
  * It would also be great to be able to get some Linked Data (as in JSON LD) in here as well
* Calvin: there's a lot here
